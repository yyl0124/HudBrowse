# 快捷键功能修复说明

## 🔧 问题诊断

之前的实现中，快捷键回调函数尝试在同步上下文中创建窗口，这在 Tauri 的全局快捷键管理器中会导致问题。

## ✅ 采用的成熟方案

### 核心改进

1. **创建统一的窗口管理命令**
   - 新增 `toggle_or_create_window` 命令
   - 这是一个 async 命令，能够正确处理窗口的创建和切换
   - 统一处理窗口的三种状态：不存在、最小化、可见

2. **使用 Tauri 异步运行时**
   - 在快捷键回调中使用 `tauri::async_runtime::spawn`
   - 这是 Tauri 官方推荐的在同步回调中执行异步操作的方式
   - 避免了阻塞和死锁问题

### 实现逻辑

```rust
// 快捷键回调
shortcut_manager.register(&hotkey, move || {
    let app_handle = app_clone.clone();
    let url_id = url_id_clone.clone();
    
    // 在异步运行时中执行（非阻塞）
    tauri::async_runtime::spawn(async move {
        let _ = toggle_or_create_window(url_id, app_handle).await;
    });
})
```

### 窗口状态管理

`toggle_or_create_window` 命令处理三种场景：

1. **窗口不存在** → 从缓存配置创建新窗口
2. **窗口最小化** → 恢复并聚焦
3. **窗口可见** → 最小化

## 🎯 功能特性

- ✅ **首次按快捷键**：创建并显示窗口
- ✅ **再次按快捷键**：最小化窗口  
- ✅ **第三次按快捷键**：恢复并聚焦窗口
- ✅ **配置持久化**：URL 配置在注册时缓存到 WindowManager
- ✅ **线程安全**：使用 Mutex 保护共享状态
- ✅ **非阻塞**：异步执行，不会卡住快捷键响应

## 📝 测试步骤

1. 重启应用（如果已经在运行）
2. 添加一个新网址，设置快捷键（如 `Ctrl+Alt+G`）
3. 按下快捷键 → 应该打开网址窗口
4. 再次按下快捷键 → 窗口应该最小化
5. 第三次按快捷键 → 窗口应该恢复显示

## 🔍 技术细节

### 为什么这个方案更成熟？

1. **遵循 Tauri 最佳实践**
   - 使用官方推荐的 `async_runtime::spawn`
   - 避免在回调中直接操作 UI

2. **更好的错误处理**
   - 统一命令返回 `Result<(), String>`
   - 错误信息清晰，便于调试

3. **资源管理优化**
   - 配置缓存避免重复序列化
   - 窗口实例集中管理

4. **可扩展性强**
   - 统一入口便于添加新功能
   - 清晰的职责分离
