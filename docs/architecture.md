# 架构说明

HudBrowse 是一个 Windows 桌面应用，不包含独立后端服务。React 前端负责配置、列表、设置和交互；Tauri/Rust 负责窗口生命周期、Win32 调用、全局快捷键、系统托盘和会话持久化。

## 分层

```text
React + Zustand
  ├─ 页面与组件：目标列表、设置、场景、捕获窗口、灵动岛
  ├─ Hooks：配置加载、窗口状态、快捷键和会话同步
  └─ services：统一目标调度、图标和 Tauri IPC
          │
          ▼
Tauri commands / Rust
  ├─ 目标调度：网页目标、桌面捕获目标、场景
  ├─ 窗口能力：创建、显示、隐藏、移动、尺寸、置顶、透明度和穿透
  ├─ Win32：窗口枚举、身份校验、图标读取和进程状态
  ├─ WebView2：用户数据目录、网页动作和页面休眠
  └─ 应用生命周期：托盘、开机启动、会话恢复和退出清理
```

## 关键数据模型

- `UrlConfig`：统一表示网址、捕获窗口和场景。场景只保存有序 `memberIds`，不复制成员配置。
- `WindowSettings`：透明度、移出隐藏、鼠标穿透、贴边隐藏、置顶和默认尺寸。
- `GlobalConfig`：主题、全局窗口默认值、开机启动、托盘、关闭行为和会话恢复。
- `TargetState`：目标是否存在、可见、最小化以及当前几何信息。
- `TargetCategory`：目标分类的名称、稳定 ID 和颜色。

## 配置继承

设置页的窗口选项是全局默认值。目标的 `settings` 为空时继承全局默认；存在时只使用该目标的独立配置。恢复“继承全局默认”会删除目标级设置，不会复制一份静态值。默认尺寸只用于首次创建，已有窗口位置和尺寸由会话/目标状态维护。

## 目标生命周期

1. 前端加载并迁移本地配置，校验目标、快捷键、分类和场景成员。
2. `sync_targets` 将前端目标配置交给 Rust 的统一窗口管理器。
3. 快捷键、列表按钮和灵动岛都通过同一套 target service 调度，避免网页目标和捕获目标走不同的状态机。
4. 捕获窗口通过进程和窗口身份校验重连；网页目标按目标 ID 使用持久化 WebView2 数据目录。
5. 外部窗口事件和轮询更新目标状态；退出时保存会话并恢复捕获窗口的原始样式、透明度、置顶和可见性。

## Rust 模块

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 应用组装、命令注册、托盘事件、主窗口关闭和退出清理 |
| `models.rs` | 配置、状态和输入校验模型 |
| `targets.rs` | 网页、捕获窗口和场景的统一调度命令 |
| `window_manager.rs` | 目标配置、原始窗口状态和运行时注册表 |
| `browser.rs` | WebView2 窗口创建、数据目录、显隐和设置应用 |
| `captured.rs` | 捕获窗口设置、状态和原始状态恢复 |
| `window_capture.rs` | Win32 枚举、候选匹配、窗口身份和基础操作 |
| `window_monitor.rs` | 外部窗口隐藏监视和进程退出处理 |
| `geometry.rs` | 多显示器工作区、DPI 和负坐标边界 |
| `shell.rs` / `island_dock.rs` | 主窗口异形区域、展开态和灵动岛态 |
| `session.rs` | 会话版本、原子保存和恢复 |
| `app_settings.rs` | 注册表开机启动、托盘和关闭行为 |
| `page_data.rs` / `web_caption.rs` | WebView2 页面数据操作、网页标题栏和休眠 |

## 重要边界

- 网页窗口是 WebView2，不是捕获的外部 HWND；桌面窗口目标不会被 HudBrowse 进程接管。
- 主窗口退出和“关闭目标窗口”是两条路径，退出时只清理 HudBrowse 自己创建的资源，并恢复捕获窗口原状。
- WebView2 是多进程架构，灵动岛收缩不会自动销毁网页 renderer；性能优化应优先考虑网页休眠和数据目录复用。
